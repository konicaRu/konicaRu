<a id="case-1"></a>

## 1. A/B-тест напоминаний о долге → +10% конверсии в оплату

**Контекст.** Финтех-платформа, работающая с оплатой ЖКУ. Часть должников месяцами не платят по счёту, и стандартная реакция — считать их неплатёжеспособными.

**Гипотеза.** Сегментировал базу должников по глубине просрочки и поведению и заметил: заметная доля не платит не потому, что не может, а потому что забывает или не видит счёт вовремя.

**Что сделал.** Спроектировал A/B-тест: тестовая группа получала напоминания о долге через банк-партнёр, контрольная — нет. Замерил конверсию в оплату по группам.

**Результат.** Конверсия в оплату в тестовой группе выросла на **+10%**. Результат лёг в основу решения о запуске сервиса напоминаний как отдельного продукта.

<a id="case-2"></a>

## 2. ABCD-тест новых страниц каталога → +6% конверсии, путь короче на 2 дня

**Контекст.** B2B-площадка электронных торгов. Нужно было проверить редизайн ключевых страниц поставщика — «Рабочего места» и «Главной».

**Что сделал.** Спроектировал дашборд для мониторинга ABCD-теста (4 версии интерфейса одновременно): свёл тестовые группы, считал конверсию в первое участие и в оплату тарифа.

**Результат.** Новая версия дала **+6%** конверсии в оплату и сократила путь от первого визита до оплаты на **2 дня**. Фичу раскатили на всю аудиторию.

<a id="case-3"></a>

## 3. RFM-сегментация → отток «уходящих» клиентов −4,5%

**Контекст.** Та же B2B-площадка: часть поставщиков переставала быть активной без явного разрыва отношений — просто постепенно снижала частоту участий.

**Что сделал.** Провёл RFM-анализ базы поставщиков (частота, сумма оплат, давность последнего участия, число побед), выделил 5 сегментов — от «чемпионов» до «потерянных». Отдельно вычленил сегмент «на грани оттока» (давность 60–90 дней, около 12% базы) и настроил под него точечные коммуникации.

**Результат.** Около **9%** сегмента «на грани оттока» вернулись к активности за квартал, общий отток по базе снизился на **−4,5%**.

## 4. LLM-разметка тональности обращений → доля негатива −18%

**Контекст.** Нужно было понять, чем недовольны пользователи поиска на платформе, не читая вручную тысячи обращений и отзывов.

**Что сделал.** Локальной LLM разметил тональность и темы обращений за полугодие, выделил топ-3 повторяющиеся жалобы (нерелевантная выдача, медленная загрузка, нехватка фильтров). Передал разбор в продуктовую команду с приоритизацией по частоте.

**Результат.** После доработок по итогам разбора доля негативных обращений снизилась на **−18%** за квартал.

## 5. Финмодель нового тарифа → прогноз +10%, факт +8% выручки

**Контекст.** Нужно было обосновать запуск нового тарифа для продавцов на B2B-площадке до того, как тратить ресурсы разработки.

**Что сделал.** На статистике оплат за два предыдущих года построил финансовую модель запуска тарифа: спрогнозировал прирост выручки от участников на квартал вперёд.

**Результат.** Прогноз — **+10%** выручки за квартал. После запуска фактический прирост выручки от участников процедур составил **+8%** за первый квартал — гипотеза подтвердилась, модель признана рабочей для будущих тарифных решений.

<a id="case-6"></a>

## 6. Локальная RAG-система по базе знаний компании

**Контекст.** В компании с давней базой знаний в Confluence — классическая проблема: поиск находит либо точное совпадение по названию страницы, либо ничего. Новый сотрудник за первый месяц задаёт одни и те же вопросы разным людям, потому что нужную страницу не может найти сам.

**Что сделал.** Самостоятельно, без задачи «сверху», собрал локальную RAG-систему: выгрузка страниц из Confluence по API → эмбеддинги (bge-m3) → двухэтапный отбор (близость по смыслу + оценка релевантности через LLM) → реранкер → чат с ответами и ссылками на источники. Жёсткое требование — данные не должны покидать контур компании, поэтому всё работает на локальных моделях без единого внешнего API-вызова.

**Результат.** В проде на реальной документации — около 1300 проиндексированных документов, ответ за 5–20 секунд. Ускоряет онбординг и поиск информации внутри команды.

Публичная (анонимизированная) версия с разбором архитектуры — **[Local RAG Pipeline](https://github.com/konicaRu/a3_product_759_RAG_public)**.

<a id="case-7"></a>

## 7. Карта поставщиков по регионам + ML-прогноз потенциала

**Контекст.** Нужно было понять, в какие регионы РФ есть смысл вкладывать усилия по привлечению новых поставщиков, а какие уже близки к насыщению.

**Что сделал.** Сопоставил плотность населения с текущим покрытием и проникновением лицевых счетов по регионам, построил карту поставщиков. Поверх карты добавил ML-модель, прогнозирующую потенциал региона по совокупности факторов.

**Результат.** Выявил 10 регионов с высоким потенциалом, которые по предварительной оценке могли дать прирост валовой прибыли на **15–20%** — вывод передан команде для приоритизации экспансии.
